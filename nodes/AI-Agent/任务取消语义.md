# 任务取消语义

## 描述

取消不是一个动作而是一段协议：服务端先把任务从 `RUNNING` 原子更新为 `CANCELLING`，再向 Worker 发送取消信号；Worker 收尾完成后才转为 `CANCELLED`。如果当前操作不可取消，不能伪造“已取消”，应停留在 `CANCELLING` 直到收到明确结果、超时或进入人工处理队列。

## 核心内容

### 用户主动取消

Worker 收到信号后：

1. 不再发起新的 LLM 请求；
2. 不再启动新的工具调用；
3. 尝试取消当前可取消的请求；
4. 等待已发出的外部操作进入可确认状态；
5. 写入最终结果并转为 `CANCELLED`。

### 新指令抢占

新指令不等于取消旧任务。先判断新指令是继续、修改、取消并新建，还是与当前任务无关；只有明确产生抢占关系时才取消旧任务。新任务应携带 `parent_task_id` 或 `supersedes_task_id`，保证审计链完整。

### 超时终止

超时至少分三种：单次 LLM 请求超时、单次工具调用超时、整个任务超过截止时间。局部超时可以重试或跳过；任务级超时进入 `CANCELLING`，执行与用户取消相同的收尾流程。重试必须使用幂等键（见 [[外部副作用与幂等键]]）。
