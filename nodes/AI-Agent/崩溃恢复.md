# 崩溃恢复

## 描述

恢复流程不能简单地从“最后一个成功步骤”继续，而应先扫描未决操作。这和 [[任务暂停与恢复]] 的区别是：暂停是有序保存后停下，崩溃是没有机会保存。

## 核心内容

```text
读取任务状态
  -> 查找未完成的工具调用
  -> 使用幂等键查询外部结果
  -> 已成功：补写结果
  -> 未执行：安全重试
  -> 状态未知：保持待确认，不自动重复副作用
```

任务状态、事件日志和工具结果应具备可追溯关联，至少能通过 `task_id` 和 `tool_call_id` 还原完整过程。由 Recovery Worker 负责处理超时、崩溃和状态未知的操作。

## 关系
- 依赖:: [[外部副作用与幂等键]] — 用幂等键查询外部结果
- 依赖:: [[Agent事件日志]] — 靠 task_id / tool_call_id 还原过程
- 对比:: [[任务暂停与恢复]] — 有序暂停 vs 无预警崩溃
