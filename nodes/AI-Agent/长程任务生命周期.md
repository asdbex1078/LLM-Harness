# 长程任务生命周期

## 描述

长程任务同时包含模型推理、工具执行和外部副作用三类工作。“终止任务”不是设置一个布尔变量，而是一个带持久化状态、取消协议和收尾流程的生命周期管理问题。任务状态必须持久化，而不是只保存在 Worker 内存中。

## 核心内容

```text
CREATED -> RUNNING -> SUCCEEDED
                   -> FAILED
                   -> TIMED_OUT
                   -> CANCELLING -> CANCELLED
                   -> PAUSING -> PAUSED -> RESUMING -> RUNNING
```

状态转换必须由服务端原子更新，并记录 `version` 或等价的乐观锁字段（见 [[乐观锁]]），避免“取消请求”和“任务完成回写”同时到达时互相覆盖。

每个任务至少保存：

- `task_id`、`status`、`version`
- 当前阶段和下一步动作
- 已完成的工具调用及其结果引用
- 仍在执行的请求 ID
- 取消原因、操作者和时间
- 最近一次心跳和最后更新时间

用户点击“停止”时，系统要分别回答三个问题：还允许 Agent 做下一步决策吗？当前请求能否被取消？已发出的外部操作如何确认、重试或补偿？这三个问题分别对应 [[取消检查点]]、[[任务取消语义]] 和 [[外部副作用与幂等键]]。
